# Завести клуб из JSON-описания

`scripts/club-setup.mjs` создаёт структуру клуба через публичный API, как это сделал бы владелец в админке:
залы, направления и их руководители, тренеры, группы с недельным расписанием, тарифы, шкалы поясов,
страница «О клубе» (правила, контакты, ссылки) и настройки. Учеников потом загружают через «Импорт клуба» (CSV).

Пример на вымышленном клубе — `scripts/club-setup.example.json`. Настоящие данные клубов в репозиторий не кладём.

## Порядок

1. Создать клуб: консоль платформы → «Создать клуб» (почта владельца, часовой пояс, например `Asia/Tomsk`)
   или самостоятельная регистрация.
2. Владелец один раз входит в админку: согласие на обработку ПДн и оферта.
3. Пробный прогон — ничего не меняет, показывает план и ошибки файла:

   ```
   node scripts/club-setup.mjs club.json --api https://api.example.ru --email owner@club.ru --dry-run
   ```

4. Настоящий прогон — та же команда без `--dry-run`. Скрипт пришлёт код на почту владельца и спросит его в терминале.
   Неинтерактивно: `CLUBSPACE_CODE=123456` (код запросить заранее) или `CLUBSPACE_TOKEN=<access token>`.

Нужен только Node 20+, пакеты не нужны: скрипт можно запускать с любого компьютера.

## Повторный запуск

Безопасен. Всё сопоставляется по названию: группы — по названию и залу, занятия — по дню и времени,
сотрудники — по e-mail. Создаётся только недостающее, изменённые поля обновляются (адрес зала, цена тарифа,
тренер группы, длительность занятия). Ничего не удаляется: то, что есть в клубе, но нет в файле, перечисляется в конце.

Файл проверяется целиком до первого запроса: неверный e-mail, несуществующий зал у группы или непонятное
расписание — ошибка со списком, клуб не меняется.

## Формат

| Раздел | Поля |
|---|---|
| `club` | `name` (как в консоли), `key` (необязательно), `timezone`, `settings` — поля `PATCH /settings` (`joinAutoApprove`, `coachesMarkAnyClass`, …) |
| `sendInvites` | `true` — тренерам уходит письмо-приглашение; по умолчанию `false` (раздать вход самому) |
| `about` | `rules` (текст), `contacts` `[{label, phone}]`, `links` `[{label, url}]` |
| `gyms` | `key`, `name`, `address` |
| `directions` | `key`, `name`, `color`, `icon`, `managers` — ключи сотрудников-руководителей |
| `staff` | `key`, `email`, `firstname`, `lastname`, `role`: `coach` (по умолчанию), `head_coach`, `admin` |
| `groups` | `name`, `gym`, `direction`, `coach`, `coaches` (вторые тренеры), `schedule` |
| `plans` | `name`, `price` (₽), `days`, `classes` (`null` — безлимит), `startsOnFirstVisit`, `directions`, `description`, `purchasableOnline` |
| `ladders` | `name`, `direction`, `audience`, `maxStripes`, `levels` `[{name, color, maxStripes, minVisits, minWeeks, requirements}]` |

Расписание группы — строки `"Пн Ср Пт 19:00-20:30"` или `"Сб 11:00 60"` (длительность в минутах),
либо объекты `{ "days": ["вт", "чт"], "time": "20:00", "minutes": 90 }`.

Ссылки между разделами — по `key` (или по названию). Группы с одинаковым названием в разных залах лучше называть
с залом: «Дети Старшие · Юпитер» — так их не перепутают ни в админке, ни в файле импорта учеников.

Новый сотрудник получает аккаунт и сразу становится тренером клуба. Если у человека уже есть аккаунт ClubSpace,
ему уходит приглашение: пока он его не примет, его группы не создаются — скрипт предупредит, после принятия
запустите его ещё раз.
