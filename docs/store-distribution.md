# Публикация в магазинах приложений

Как ClubSpace попадает к ученикам: одно нейтральное приложение «ClubSpace» во
всех магазинах, брендовые приложения клубов — отдельной услугой из аккаунтов
самих клубов, PWA — как запасной путь. Здесь же правила магазинов, которые
определяют эту схему, настройка аккаунта для проверки и чек-лист релиза.

Правила магазинов меняются; ссылки на первоисточники — в конце документа.
Пометка `[ВЫВОД]` означает нашу интерпретацию, а не цитату из правил.

## 1. Схема распространения

| Что | Кто публикует | Идентификатор | Профили EAS |
|---|---|---|---|
| **ClubSpace** — нейтральное приложение, выбор клуба по коду, ссылке, QR | ClubSpace, наши аккаунты разработчика | `com.clubspace.app`, схема `clubspace://` | `preview`, `production` (APK), `store` (AAB / App Store) |
| **Брендовое приложение клуба** — тот же код, клуб «зашит» внутрь | Клуб, из своего аккаунта разработчика | свой (`ru.myclub.app`), своя схема | `branded` (APK), `branded-store` (AAB / App Store) |
| **PWA** — то же приложение в браузере, ставится на домашний экран | ClubSpace (или владелец инсталляции) на `app.<домен>` | — | `npm run build:pwa` |

Почему так:

- **Apple 4.2.6.** Приложения из коммерческого шаблона отклоняются, если их
  подаёт не владелец контента. Разрешённая альтернатива — «единый бинарник со
  всеми клиентами в модели агрегатора или picker». Нейтральный ClubSpace —
  именно такой picker; брендовое приложение законно, только если его подаёт сам
  клуб из своего аккаунта. Так же устроены Mindbody, Glofox, PushPress, Wodify,
  Mariana Tek.
- **Apple 4.3(a).** Не плодить Bundle ID одного и того же приложения «для разных
  городов, команд, университетов» — Apple прямо советует одно приложение.
- **RuStore §4.6** запрещает «множественные публикации одного и того же
  приложения» с минимальными отличиями. Массовые клоны из одного аккаунта —
  риск модерации.
- Член нескольких клубов (BJJ + йога + зал) ставит одно приложение и
  переключается между клубами, а не держит три.

Что видит ученик: ставит ClubSpace, входит по коду из письма, открывает
ссылку или QR клуба — и клуб появляется в приложении. Брендовое приложение
клуба работает с тем же аккаунтом: тот же e-mail открывает те же клубы в обоих.

## 2. Нейтральное приложение ClubSpace

Конфигурация — `apps/mobile/app.config.js` → `src/app-variant.js`; статического
`app.json` больше нет.

- Название «ClubSpace», Bundle ID и Android package `com.clubspace.app`,
  URL-схема `clubspace`, иконки из `apps/mobile/assets/images/`.
- Slug EAS остаётся `grappling-academy-mobile`: под ним в EAS лежат keystore
  Android и счётчик версий. Переименование создаст новый проект EAS с новым
  keystore — уже установленные приложения не смогут обновиться.
- `EXPO_PUBLIC_CLUB_PICKER=true`, `EXPO_PUBLIC_BRAND=clubspace`, клуб не зашит.
  Значения API, веб-адреса и почты поддержки записывает
  `scripts/set-mobile-target.sh --domain <домен> --support-email <почта>`.
- Переменные брендовой сборки (`EXPO_PUBLIC_APP_NAME`, `EXPO_PUBLIC_BUNDLE_ID`,
  `APP_ASSETS_DIR` …) в этом режиме игнорируются — случайно «перекрасить»
  каноническую карточку магазина нельзя.

### Ссылки `https://app.<домен>/join/<код>`

Приложение заявляет `applinks:<хост EXPO_PUBLIC_WEB_URL>` (iOS) и intent-filter
`https://<хост>/join/*` с `autoVerify` (Android). Чтобы ссылка открывала
приложение, а не браузер, веб-сервер `app.<домен>` (`apps/client`) отдаёт
`/.well-known/apple-app-site-association` и `/.well-known/assetlinks.json` из
переменных окружения контейнера `client`:

- `APPLE_TEAM_ID` — Team ID аккаунта Apple;
- `IOS_BUNDLE_ID` — через запятую, например `com.clubspace.app`;
- `ANDROID_PACKAGE` — через запятую, например `com.clubspace.app`;
- `ANDROID_CERT_SHA256` — отпечатки SHA-256 через запятую: ключ подписи
  приложения из Play Console и ключ EAS (для APK вне магазина).

Пока подтверждения нет, ссылка открывает PWA — вступить в клуб можно и там.
Кнопки магазинов на странице `/join` и в письмах берутся из `APP_STORE_URL`,
`PLAY_STORE_URL`, `RUSTORE_URL`.

## 3. Брендовое приложение клуба (платная услуга)

Тот же код с зашитым клубом. Публикуется **только из аккаунтов разработчика
клуба** — иначе 4.2.6/4.3(a) в App Store и §4.6 в RuStore.

### Процесс

1. **Клуб заводит аккаунты** (на юрлицо или ИП клуба):
   - Apple Developer Program (организация, D-U-N-S), добавляет ClubSpace в
     команду App Store Connect с ролью App Manager или Developer;
   - Google Play Console, приглашает ClubSpace пользователем с правами на
     релизы;
   - RuStore Консоль (VK ID, юрлицо / ИП / самозанятый), добавляет ClubSpace
     в команду.
2. **Проект EAS для клуба.** Отдельный проект Expo (в организации клуба или в
   нашей, с доступом клуба). В нём — переменные окружения среды `production`
   (`eas env:create --environment production …`); их читают профили
   `branded` / `branded-store`:

   | Переменная | Обяз. | Что это |
   |---|---|---|
   | `EXPO_PUBLIC_APP_NAME` | да | Название на иконке и в магазине, оно же заголовок экрана входа |
   | `EXPO_PUBLIC_BUNDLE_ID` | да | Bundle ID / package клуба, например `ru.kimura.app`; **не** `com.clubspace.*` |
   | `APP_ASSETS_DIR` | да | Папка (относительно `apps/mobile`) с `icon.png`, `adaptive-icon.png`, `splash-icon.png`, `favicon.png` — свои, не иконка ClubSpace |
   | `EXPO_PUBLIC_WORKSPACE_KEY` | да | Ключ клуба из `/platform` |
   | `EXPO_PUBLIC_BRAND` | да | Пресет текстов и цвета: `grappling`, `fitness`, `yoga`, `clubspace`, `custom` |
   | `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_WEB_URL`, `EXPO_PUBLIC_SUPPORT_EMAIL` | да | Сервер, веб-адрес (юридические страницы, ссылки), почта поддержки |
   | `EAS_PROJECT_ID` | для push | ID этого проекта EAS |
   | `GOOGLE_SERVICES_FILE` | для push на Android | `google-services.json` проекта Firebase клуба (файловая переменная EAS) |
   | `EXPO_PUBLIC_APP_COLOR` | нет | `#rrggbb` — цвет уведомлений и темы PWA |
   | `EXPO_PUBLIC_APP_SCHEME` | нет | URL-схема; по умолчанию Bundle ID строчными |
   | `EXPO_PUBLIC_APP_SLUG` | нет | Slug проекта EAS; по умолчанию Bundle ID через дефисы |

   В `eas.json` этих значений нет намеренно: значения из `eas.json` перекрывают
   переменные EAS.
3. **Сборка и отправка:**

   ```bash
   cd apps/mobile
   npx eas build --profile branded-store --platform all
   npx eas submit --profile branded-store --platform android
   npx eas submit --profile branded-store --platform ios
   ```

   Сертификаты iOS и APNs-ключ создаются в команде Apple клуба
   (`npx eas credentials`). Первую загрузку в Play делают вручную.
4. **Ссылки.** Брендовое приложение заявляет `/join/*` на хосте своего
   `EXPO_PUBLIC_WEB_URL`. На общем хосте платформы в `.well-known` указывайте
   только ClubSpace: `APPLE_TEAM_ID` там один, а Team ID у клуба свой.
   Брендовому приложению нужен собственный хост (своя инсталляция или домен
   клуба).

`scripts/check-release-env.mjs` отказывается собирать брендовый профиль без
названия, Bundle ID, ключа клуба или иконок, с Bundle ID `com.clubspace.*`, с
иконкой ClubSpace, со схемой `clubspace` или с `EXPO_PUBLIC_CLUB_PICKER=true`.

## 4. Правила магазинов, которые нас касаются

### Apple App Store

- **3.1.1 / 3.1.3(e) — оплата.** Абонементы, разовые занятия, персональные
  тренировки — это физические услуги, потребляемые вне приложения. Их **нельзя**
  продавать через In-App Purchase: только карта / эквайринг / оплата в клубе.
  В приложении сейчас нет никакой оплаты — администратор отмечает оплату
  абонемента вручную; так и оставляем.
- **3.1.1 — цифровой контент.** Видеокурсы, продаваемые как отдельный
  цифровой продукт, внутри iOS-приложения требуют IAP. Механизмы «разблокировки»
  своими силами (коды, QR) запрещены. Варианты:
  - курсы входят в абонемент клуба и выдаются клубом, в приложении нет
    призывов купить — модель reader-приложения (3.1.3(a)); так делают BJJ
    Fanatics и MGinAction `[ВЫВОД]`;
  - отдельные курсы продаются на сайте, iOS-приложение на сайт за покупкой не
    ведёт;
  - **США:** с мая 2025 ссылки и кнопки на оплату вне приложения в
    американской витрине разрешены без entitlement; комиссия за такие покупки
    пока не установлена;
  - **ЕС (DMA):** с 1 октября 2026 единые условия — IAP 26 % (15 % малый
    бизнес), альтернативный процессинг 20 % / 10 %, ссылка на внешнее
    предложение 15 % / 10 %; выбранный вариант держится 12 месяцев.
- **3.1.3(d).** Живые занятия «один на один» могут обходиться без IAP;
  платные онлайн-трансляции «один ко многим», продаваемые в приложении, — только
  через IAP. Трансляции внутри абонемента клуба — серая зона `[ВЫВОД]`.
- **5.1.1(v) — удаление аккаунта.** Есть: Профиль → Настройки → «Удалить
  аккаунт» (`DELETE /me`) и веб-страница `/legal/delete-account`. Удаляется весь
  аккаунт, не только членство в клубе. Владельцу клуба и тренеру группы
  предлагается сначала передать дела.
- **4.8 — вход.** Вход по коду на почту не требует «Sign in with Apple».
  Если добавим вход через Google или VK — понадобится равноценный вход,
  сохраняющий приватность.
- **1.2 — пользовательский контент.** Для ленты/чатов нужны фильтрация, жалобы,
  блокировка и опубликованные контакты. Жалоба на контент в приложении есть
  (`content.report`).
- **5.1.2.** Передача данных третьим лицам (в том числе сторонним AI) — только
  с явного разрешения.

### Google Play

- **Платёжная политика.** Play Billing обязателен для цифрового контента и
  **запрещён** для оплаты физических услуг — прямо названы абонементы в зал и
  билеты на мероприятия. Подписки на фитнес-, образовательный и видеоконтент —
  случай Play Billing.
- **США:** после Epic v. Google доступны альтернативный биллинг и внешние
  ссылки по программам Google, со своими комиссиями.
- **Россия:** биллинг Play приостановлен с 10 марта 2022; бесплатные
  приложения распространяются.
- **Удаление аккаунта** — в приложении и по веб-ссылке (есть, см. выше);
  ссылку `https://app.<домен>/legal/delete-account` указываем в Data safety.

### RuStore

- **§9.1:** все способы оплаты (IAP, сторонний эквайринг, свои решения)
  декларируются в консоли; незадекларированные запрещены. Сейчас платежей в
  приложении нет — декларировать нечего; при подключении эквайринга —
  задекларировать до релиза.
- **§5.1:** обязательна политика конфиденциальности по 152-ФЗ —
  `https://app.<домен>/legal/privacy`.
- **§4.6:** запрет множественных публикаций одного приложения (см. раздел 1).
- Лимит публикаций: до 10 приложений в день для физлиц, для юрлиц —
  индивидуально. Аккаунт — через VK ID, юрлицо / ИП / физлицо.
- С 1 сентября 2025 RuStore обязателен к предустановке на смартфоны,
  продаваемые в России.
- **Push.** В RuStore публикуется тот же AAB/APK. Уведомления идут через Expo
  → FCM, поэтому **на телефонах без сервисов Google** (Huawei, часть
  «российских» прошивок) push не придут `[ВЫВОД]`. RuStore Push SDK потребует
  отдельной нативной зависимости и серверного канала отправки — в текущую
  сборку не входит. Пока такие ученики видят уведомления во «Входящих»
  приложения и получают письма.

### App Store и российские разработчики

- С 1 апреля 2026 Apple остановила приём платежей в App Store в России;
  покупки и продления — только с остатка баланса. Любая монетизация через IAP
  в России невозможна `[ВЫВОД]`.
- Приложения удаляются по требованию регулятора (отчёт о прозрачности Apple
  за 2025), в июне 2026 из App Store удалили приложения VK.
- Аккаунт Apple Developer для российского юрлица оформить и оплачивать
  затруднительно; публикация через иностранное юрлицо — отдельное
  юридическое решение `[ВЫВОД]`.
- **Поэтому PWA обязательна как запасной путь**: `app.<домен>` открывается в
  Safari, «На экран Домой» ставит приложение с иконкой и названием бренда
  (манифест генерирует `scripts/build-pwa.mjs`). Работает всё, кроме нативных
  push и офлайн-загрузки видео. Ссылки `/join/<код>` при отсутствии
  приложения открывают PWA.

## 5. Аккаунт для проверки магазинами

Ревьюеры не читают нашу почту, поэтому один адрес входит по фиксированному
коду. Переменные сервера (`.env.production`):

```
STORE_REVIEW_EMAIL=review@clubspace.ru
STORE_REVIEW_CODE=<6 случайных цифр: LC_ALL=C tr -dc 0-9 </dev/urandom | head -c6>
STORE_REVIEW_WORKSPACE_KEY=<ключ демо-клуба>
```

- Код проверяется при старте: оба значения или ни одного, не угадываемый
  (не `123456`, `111111` …), адрес не совпадает с `SUPER_ADMIN_EMAIL`.
  `STORE_REVIEW_WORKSPACE_KEY` без первых двух сервер тоже не примет.
- Аккаунт сам не создаётся: пригласите адрес в демо-клуб из админки
  (Участники → «Пригласить учеников») или войдите им один раз обычным кодом
  до того, как задать переменные.
- Фиксированный код открывает только аккаунт обычного ученика: администратор
  платформы, владелец клуба или тренер с этим адресом не войдёт.
- **Демо-клуб.** При каждом входе ревьюера с заданным
  `STORE_REVIEW_WORKSPACE_KEY` сервер делает его АКТИВНЫМ учеником этого клуба:
  создаёт членство, снимает «ожидает» / «заблокирован» / «приостановлен» и
  истёкший срок доступа. Если всё уже в порядке — ничего не пишет. Каждое
  изменение — событие «Аккаунт проверки магазина добавлен в демо-клуб» в
  журнале клуба и платформы; сам вход — «Вход аккаунта для проверки магазина
  приложений». Неверный ключ клуба вход не ломает, только пишет предупреждение
  в лог.
- Демо-клуб должен выглядеть живым: расписание на ближайшие недели, пара
  курсов с видео, объявления, пояса — ревьюер оценивает «полноценность»
  приложения (Apple 2.1 / 4.2).
- Не удаляйте переменные после первого релиза: каждое обновление проверяют
  заново.

Текст для App Review Information / «Доступ к приложению» в Play Console:

> Вход по коду из письма. Для проверки: e-mail `review@clubspace.ru`, нажмите
> «Получить код», введите код `<STORE_REVIEW_CODE>`. Аккаунт уже состоит в
> демо-клубе «<название>»: расписание, курсы, абонемент. Удаление аккаунта:
> Профиль → Настройки → «Удалить аккаунт».

## 6. Push-уведомления

- `expo-notifications` подключён плагином в конфиге (`app-variant.js`).
- `EAS_PROJECT_ID` → `extra.eas.projectId`: по нему Expo выдаёт push-токены.
- `GOOGLE_SERVICES_FILE` → `android.googleServicesFile`: конфигурация FCM.
  Задайте файловой переменной EAS
  (`eas env:create --type file --name GOOGLE_SERVICES_FILE …`); файл в
  репозиторий не коммитится.
- iOS: APNs-ключ загружается через `npx eas credentials` в команду Apple
  владельца приложения.
- Проверка релиза **предупреждает** (сборку не останавливает), если нет
  `EAS_PROJECT_ID` или — для Android — `GOOGLE_SERVICES_FILE`; заданный, но
  отсутствующий файл — ошибка.
- В PWA push нет (web push не реализован).

## 7. Что меняется для текущих установок (миграция)

До этого изменения профили `production` / `store` собирали брендовое
приложение «Грэпплинг Академия» с зашитым клубом под `com.clubspace.app`.
Теперь под тем же идентификатором выходит нейтральный ClubSpace.

- **Обновление поверх старой версии работает:** тот же package, тот же slug и
  keystore EAS. После обновления у ученика на иконке «ClubSpace» вместо
  «Грэпплинг Академия».
- **Ученики клуба не теряют клуб:** членство хранится на сервере, приложение
  показывает клубы аккаунта. Заявки «на рассмотрении» остаются.
- **Новые ученики** больше не попадают в клуб автоматически при входе: им нужен
  код, ссылка или QR клуба (или приглашение по e-mail из админки). Обновите
  плакаты и сообщения в чатах клуба на ссылку `/join/<код>`.
- **Схема `grappling-academy://`** больше не регистрируется; в коде и письмах
  она не использовалась.
- **Профили `club-picker` / `club-picker-store` удалены** — это теперь
  `production` / `store`. `set-mobile-target.sh` больше не принимает
  `--club-key`.
- **Карточки магазинов:** переименуйте приложение в ClubSpace, обновите
  описание (приложение для учеников любых клубов), скриншоты и иконку.
- **Если клубу нужен прежний брендовый вид** — это брендовое приложение из его
  аккаунта с **новым** Bundle ID. Это отдельная карточка: ученики ставят её
  заново, вход тем же e-mail.
- PWA устанавливается под именем бренда сборки (для нейтральной — «ClubSpace»),
  а не «Грэпплинг Академия».

## 8. Чек-лист релиза

Каждый релиз:

- [ ] `npm run verify` зелёный; версия собирается из `production`/`store`.
- [ ] `eas.json`: реальные `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_WEB_URL`,
