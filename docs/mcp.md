# ИИ-ассистент: ClubSpace через MCP

Владелец клуба подключает ClubSpace к ИИ-ассистенту — Claude (Desktop, Code),
ChatGPT, Cursor — и спрашивает о клубе обычными словами: «кто может уйти в
этом месяце», «выручка по направлениям за полгода», «кого пора продлевать».
Ассистент получает данные через [Model Context Protocol](https://modelcontextprotocol.io)
и **только читает** — в пределах прав того, кто создал токен.

- Эндпоинт: `POST https://api.<домен>/mcp` (локально `http://localhost:3000/mcp`).
- Транспорт: Streamable HTTP, JSON-RPC 2.0, без сессий (stateless). Версии
  протокола: `2025-11-25`, `2025-06-18`, `2025-03-26`.
- Авторизация: `Authorization: Bearer csai_…` — токен клуба из админки.
- Код: `apps/server/src/features/mcp/` (транспорт, инструменты),
  `apps/server/src/features/ai-tokens/` (токены), `apps/server/src/domains/ai-assistant/`.

## 1. Создать токен

Админка → **«Интеграции» → «ИИ-ассистент»**:

1. Название — чтобы отличать токены («Claude — директор»).
2. Данные участников:
   - **«Обезличено»** (по умолчанию) — ассистент не получает имён, телефонов и
     e-mail. Участники — стабильные псевдонимы `m_0123456789`, тренеры —
     `c_…`. Один человек в одном клубе всегда под одним псевдонимом, поэтому
     ассистент может переспросить про конкретного участника (`member_profile`).
     Поиск по имени в этом режиме отключён — он позволил бы угадывать людей.
   - **«С персональными данными»** — имена, телефоны и e-mail участников (у
     тренеров — только имя). Включает **только владелец клуба** и только после
     явного согласия с предупреждением о передаче персональных данных
     стороннему, как правило иностранному, ИИ-сервису (152-ФЗ, ст. 12).
     Согласие сохраняется как доказательство (`AiDataTransferAcceptance`: кто,
     какая редакция текста, когда, IP, браузер) и попадает в «Историю изменений».
3. Срок: 30, 90, 365 дней или бессрочно.
4. «Создать» → токен показывается **один раз** (хранится только SHA-256).
   Там же готовые настройки для Claude Code, Claude Desktop и Cursor.

Кто может создавать:

| Кто | Что видит ассистент |
|---|---|
| Владелец, администратор, главный тренер | Весь клуб, включая выручку и долги |
| Руководитель направления | Только свои направления: их группы и учеников, занятия, события, лестницы рангов, тарифы. Финансовых инструментов нет |
| Тренер без направления, ученик | Нельзя |

Права токена = **текущие** права создателя: каждый запрос заново проверяет
его роль и направления. Сняли с руководства, удалили из клуба, заблокировали —
токен перестаёт работать сразу. Клуб приостановлен — тоже.

Список токенов показывает состояние, создателя, срок и «последний запрос».
Администратор отзывает любой токен клуба, руководитель направления — свои.
Отзыв действует мгновенно.

## 2. Подключить клиента

Ниже `URL` — адрес из карточки (`https://api.<домен>/mcp`), `TOKEN` — `csai_…`.

### Claude Code

```bash
claude mcp add --transport http clubspace URL --header "Authorization: Bearer TOKEN"
```

### Claude Desktop

Раздел «Connectors» в Claude Desktop/claude.ai подключает удалённые серверы
только через OAuth (см. §6), поэтому сейчас — через мост
[`mcp-remote`](https://www.npmjs.com/package/mcp-remote) (нужен Node.js 18+).
Settings → Developer → Edit Config, файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "clubspace": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "URL", "--header", "Authorization:${CLUBSPACE_TOKEN}"],
      "env": { "CLUBSPACE_TOKEN": "Bearer TOKEN" }
    }
  }
}
```

Заголовок передаётся через переменную окружения без пробелов в аргументах —
так `mcp-remote` работает и в Windows. Перезапустите Claude Desktop: в списке
инструментов появится `clubspace`.

### Cursor

`~/.cursor/mcp.json` (или `.cursor/mcp.json` в проекте):

```json
{
  "mcpServers": {
    "clubspace": { "url": "URL", "headers": { "Authorization": "Bearer TOKEN" } }
  }
}
```

### ChatGPT

- **Приложение ChatGPT** (Developer mode → Connectors) подключает удалённые
  MCP-серверы с OAuth или без авторизации; произвольный заголовок с токеном
  там не задать. Подключение появится вместе с OAuth (§6).
- **OpenAI API** (Responses API, Agents SDK) — уже сейчас:

```json
{
  "type": "mcp",
  "server_label": "clubspace",
  "server_url": "URL",
  "headers": { "Authorization": "Bearer TOKEN" },
  "require_approval": "never"
}
```

### Проверка без ассистента

```bash
curl -s URL -H "Authorization: Bearer TOKEN" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"club_overview","arguments":{}}}'
```

Или `npx @modelcontextprotocol/inspector` → Transport «Streamable HTTP», URL,
заголовок `Authorization`.

## 3. Инструменты

Все только читают, ограничены клубом и правами токена. Описания и JSON-схемы
аргументов — на русском, в ответе `tools/list`. Ответ — JSON в `content[0].text`
и он же в `structuredContent`.

| Инструмент | Что отвечает | Только админ |
|---|---|---|
| `club_directory` | Направления, залы, группы (тренеры, число участников), тарифы, лестницы рангов — с id для фильтров | |
| `club_overview` | Ученики, посещаемость за 7/30 дней, абонементы, риск оттока, ближайшие события и аттестации; для админа — выручка за 30 дней и месяц, долг | |
| `revenue_report` | Выручка за N месяцев по месяцам / тарифам / направлениям | ✓ |
| `search_members` | Ученики с фильтрами (статус, направление, группа, есть ли абонемент), поиск | |
| `member_profile` | Карточка ученика по `ref`: группы, абонементы, посещения, ранги, аттестации, риск | |
| `at_risk_members` | «Кто пропадает»: причина, пояснение, последний визит, последний контакт | |
| `renewals_due` | Кому продлевать: закончились / заканчиваются занятия или срок | ✓ |
| `unpaid_abonements` | Долги: неоплаченные абонементы и сумма | ✓ |
| `abonement_states` | Абонементы по состояниям (заморожен, ждёт первой тренировки, закончились занятия, скоро закончится, действует, закончился) и по тарифам | |
| `schedule` | Расписание и события на период (до 31 дня), по залу / направлению / группе | |
| `attendance_stats` | Посещаемость за период (до 366 дней): по группам, дням недели, неделям, топ-10 | |
| `rank_distribution` | Сколько учеников на каждой ступени лестницы; ученики ступени | |
| `upcoming_gradings` | Аттестации: кандидаты, результаты, взносы | |
| `list_events` | События клуба за период, сколько пришло | |

Правила, общие для всех:

- Деньги — в целых единицах валюты клуба (рубли), выручка — только оплаченные
  абонементы по дате оплаты (как на «Обзоре»). Абонемент на несколько
  направлений в `revenue_report` делится поровну.
- Время в расписании и событиях — местное время зала/события; даты аргументов —
  `ГГГГ-ММ-ДД` в часовом поясе клуба.
- Списки постраничны: `offset`/`limit` (до 50), в ответе `total` и `nextOffset`.
  Ответ не длиннее 60 000 символов JSON — иначе обрезается с пометкой `truncated`.
- Заметки тренеров о участниках и причины заморозок (там бывают сведения о
  здоровье) не выдаются ни в каком режиме.
- Неверный id, чужое направление, деньги для руководителя направления — ответ
  инструмента с `isError: true` и объяснением по-русски, чтобы ассистент
  исправился сам.

## 4. Безопасность и журнал

- **Один клуб**: токен привязан к клубу, id из другого клуба не находятся.
- **Хранение**: в базе только SHA-256 токена и первые 10 символов для списка.
- **Лимит**: `AI_MCP_RATE_LIMIT_PER_MINUTE` (по умолчанию 60) запросов в
  минуту на токен — любой запрос к `/mcp`. Превышение — HTTP 429, заголовок
  `Retry-After`, JSON-RPC ошибка `-32029`. Счётчики в Redis, общие для реплик.
- **Журнал**: каждый `tools/call` пишется в «Историю изменений» клуба
  (`ai.toolCall`): инструмент, краткие аргументы, число строк в ответе,
  ошибка, токен, режим данных, время. Создание и отзыв токена, согласие на
  персональные данные — `ai.tokenCreate`, `ai.tokenRevoke`,
  `ai.personalDataAccept`.

Ответы протокола:

| Ситуация | HTTP | JSON-RPC |
|---|---|---|
| Запрос | 200 | `result` или ошибка |
| Уведомление (`notifications/initialized`) или ответ клиента | 202, без тела | — |
| Нет токена, неизвестный, отозван, истёк, создатель заблокирован | 401 + `WWW-Authenticate: Bearer` | `-32001` |
| У создателя больше нет прав, клуб приостановлен | 403 | `-32003` |
| Лимит | 429 + `Retry-After` | `-32029` |
| Пакет (batch), не JSON-RPC, неизвестная `MCP-Protocol-Version` | 400 | `-32600` |
| Неизвестный метод | 200 | `-32601` |
| Неизвестный инструмент, `arguments` не объект | 200 | `-32602` |
| `GET` / `DELETE /mcp` (SSE-поток и сессии не нужны) | 405 | — |

Заголовок `Origin` не проверяется: токен — не cookie, браузер не подставит его
сам, поэтому DNS-rebinding, от которого защищает эта проверка в локальных
серверах, здесь ничего не даёт.

## 5. Пример: демо-клуб ACADEMY

Демо-клуб (`docs/demo.md`): 10 залов в Томске и Северске, направления БЖЖ,
ММА и тайский бокс, ~310 учеников, полгода продаж. Войдите в админку как
`owner@`, создайте токен «обезличено», подключите Claude Desktop.

| Вопрос владельца | Что вызывает ассистент | Что видно в ответе |
|---|---|---|
| «Как дела в клубе?» | `club_overview` | ~310 учеников, посещения за неделю и месяц, ~10% под риском, выручка за 30 дней и долг по 5 абонементам |
| «Кто может уйти и почему? Начни с тех, у кого кончился абонемент» | `at_risk_members` (`reason: "lapsed"`) | Список `m_…` с пояснением («Абонемент «12 занятий» закончился …») и последним визитом; с кем уже связывались — помечены |
| «Расскажи подробнее про m_…» | `member_profile` | Группы, абонементы, посещения за 30/90 дней, пояс, риск |
| «Выручка по направлениям за полгода» | `revenue_report` (`groupBy: "direction", months: 6`) | БЖЖ, ММА, тайский бокс и «весь клуб» — суммы и число продаж |
| «А по месяцам — растём?» | `revenue_report` (`groupBy: "month"`) | Шесть месяцев с суммами |
| «Кого пора продлевать на этой неделе?» | `renewals_due` | Закончились / осталось одно занятие / срок истекает |
| «Кто нам должен?» | `unpaid_abonements` | 5 неоплаченных абонементов, сумма, сколько дней долгу |
| «Сколько абонементов заморожено и ждёт первой тренировки?» | `abonement_states` | Сводка по состояниям: 3 заморожены, ожидают первой тренировки… |
| «Какие группы во «Дворце спорта» полнее всего по вторникам?» | `club_directory` → `attendance_stats` (`gymId`) | По группам и дням недели, среднее на занятие |
| «Расписание тайского бокса на эту неделю» | `club_directory` → `schedule` (`directionId`) | Занятия Савельева в Северске по дням |
| «Кто идёт на аттестацию на синий пояс?» | `upcoming_gradings` | Аттестация через 12 дней: кандидаты `m_…`, оплачен ли сбор |
| «Сколько синих поясов в БЖЖ?» | `rank_distribution` | Ученики по ступеням лестницы |

Токен руководителя направления (`bjj@`) ответит про БЖЖ, а на «выручка по
направлениям» — что финансовые данные доступны только администратору.

В «Истории изменений» → фильтр «ИИ-ассистент» видно каждый вопрос. В демо уже
есть токен «Claude — директор» с несколькими запросами и отозванный «ChatGPT —
проба»; их секретов не существует — для показа создайте свой.

## 6. Дальше: OAuth

Сейчас авторизация — личный токен из админки. С OAuth 2.1 по
[спецификации авторизации MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization):

- подключение «в один клик» в ChatGPT (Connectors), claude.ai и Claude Desktop
  (Connectors) без копирования токена и без `mcp-remote`;
- `/.well-known/oauth-protected-resource` и `WWW-Authenticate` с
  `resource_metadata`, авторизационный сервер ClubSpace (код + PKCE,
  динамическая регистрация клиентов), экран согласия в админке: какой клуб,
  режим данных, права;
- короткоживущие access-токены с ротацией refresh-токенов вместо долгих
  личных токенов; отзыв — там же, в «Интеграциях»;
- те же правила доступа: токен = клуб + создатель + режим данных, журнал и
  лимит не меняются.

## 7. Дальше: действия (подготовлено, выключено)

Интерфейс для записывающих инструментов уже есть
(`apps/server/src/features/mcp/mcp-actions.ts`), но закрыт:

- право `actions` у токена (`AI_TOKEN_SCOPES`) пока нельзя выдать —
  `ENABLED_AI_TOKEN_SCOPES = ['read']`, создание токена с `actions`
  отклоняется; реестр `MCP_ACTION_TOOLS` пуст;
- инструменты действий видны и вызываются только токеном с `actions`, в
  `tools/list` они помечены `readOnlyHint: false, destructiveHint: true`.

**Обязательное подтверждение.** Первый вызов действия ничего не меняет и
возвращает `requiresConfirmation: true`, `preview` (что произойдёт: «Заморозить
абонемент m_… с 3 по 16 ноября», последствия — сдвиг срока, уведомления, деньги)
и код `confirmation`. Ассистент обязан показать preview человеку и повторить
вызов с теми же аргументами и `confirmation` только после явного согласия. Код
подписан HMAC и привязан к токену, инструменту и **точным** аргументам, живёт
5 минут; другие аргументы, другой токен или просроченный код отклоняются. Оба
вызова пишутся в журнал. (Когда клиенты повсеместно поддержат elicitation
MCP, подтверждение можно будет запрашивать у человека напрямую, минуя модель.)

Чтобы выпустить первое действие:

1. Реализовать `McpActionTool` (`kind: 'action'`, `preview`, `run`; в `input`
   добавить `...confirmationInput`) поверх существующего обработчика через
   `FeaturesBus` — права и аудит обработчика сохраняются (`run` вызывает
   фичу от имени создателя токена).
2. Добавить его в `MCP_ACTION_TOOLS`, `'actions'` — в `ENABLED_AI_TOKEN_SCOPES`.
3. В «Интеграциях» — переключатель «Разрешить действия» с отдельным
   предупреждением; e2e: без подтверждения ничего не меняется.

Первые кандидаты: отметить «Связались» в «Кто пропадает», заморозить
абонемент, отметить оплату, записать объявление черновиком.

## Развёртывание

- Схема: две новые таблицы (`AiAccessToken`, `AiDataTransferAcceptance`) и
  enum — `prisma db push` делает `deploy/update.sh`, ручных шагов нет.
- Необязательно: `AI_MCP_RATE_LIMIT_PER_MINUTE` в `.env.production` (по
  умолчанию 60).
- Caddy уже проксирует `api.<домен>` целиком, `/mcp` доступен без настроек.
