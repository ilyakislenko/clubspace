# Changelog

Версия мобильного приложения — `1.0.0` (`apps/mobile/src/app-variant.js`), до
первого релиза в сторах не меняется.

## Unreleased

### Видео для учёбы
- Свой плеер в мобилке: скорость списком (от 0.25x), зеркало, покадровый шаг,
  двойной тап ±10 с, 2x при удержании, полноэкранный режим, автопереход к
  следующему уроку.
- Личные закладки и заметки к видео с офлайн-синхронизацией, экран «Мои
  заметки», отрезки A–B, рисование на закладках, «поделиться моментом».
- Обложки видео из кадра, обложка курса по первому уроку.
- Автоглавы (OCR титров или речь инструктора через Whisper + ИИ), автосубтитры
  EN/RU с терминологией клуба, поиск по речи; управление в админке.
- Повторение закладок, планы тренировок (в том числе офлайн), каталог техник,
  разборы видео от тренера, сравнение двух видео рядом, напоминания.

### Разгрузка интерфейса
- Урок: не больше четырёх действий на виду, остальное в меню «⋯»; субтитры и
  A–B — в плеере по запросу.
- Курс: «Продолжить» вместо «Скачать»; главная тренера и карточки расписания
  короче, вторичные фильтры и ссылки — за одной кнопкой.
- Фильтр расписания в мобилке: несколько направлений и несколько залов сразу
  («Мои группы» — отдельно), выбор запоминается для клуба; на кнопке —
  «БЖЖ, ММА · Все залы» или «3 направления · 2 зала». API:
  `GET schedule?directionIds=a,b` вместо `directionId`.

### Чистка админки (`docs/design/2026-11-08-admin-cleanup.md`)
- Роли: деньги и система (ключи оплаты, возвраты, цены тарифов, подписка
  ClubSpace, выручка и прогноз, настройки, роли, импорт, выгрузки, история
  изменений, ИИ-токены) — только владелец и администратор (`CLUB_ADMINS`);
  главный тренер — спорт и операции (`SPORT_LEADS`). Денежные цифры сервер не
  отдаёт ниже администратора. Профили, приглашения и доступ сотрудников меняет
  только администратор. `WORKSPACE_ADMINS` удалён.
- Истёкший абонемент больше не помечен «Активен» и не предлагает «Отменить»;
  обрыв связи — «Нет связи с сервером…» вместо «Network Error»; строки видео и
  курсов — обычные ссылки; несохранённые изменения в формах больше не теряются
  молча при уходе со страницы.
- Smoke e2e админки (`apps/admin-e2e`, Playwright): обход всех страниц под
  владельцем, администратором, главным тренером и тренером, проверка запретов;
  `VERIFY_ADMIN_E2E=1 npm run verify`, CI-задача `admin-e2e`. Порог покрытия
  админки поднят до 31/27/23/29.
- Один список «Кому позвонить» вместо двух («Кто пропадает» и «Кому позвонить»
  считали по-разному): причины — по живым правилам, риск и «₽ на кону» — из
  ночного снимка; одно число в админке, на обзоре и в мобилке, «Связались»
  убирает ученика везде; кэш 60 с. `GET analytics/churn` удалён.
- «Группы и залы»: компактный список групп и вкладка залов; время меняется
  только в календаре (перерывы, снятие отмены, места по слоту, «Убрать из
  расписания с этой даты» — будущие записи отменяются с уведомлением). `GET
  groups` без составов, состав — `GET groups/:id/members` с поиском и
  страницами; учеников выбирают поиском, без выгрузки всего клуба.
- «Пересчитать» в аналитике — фоновая задача, одна на клуб, не чаще раза в
  5 минут; готовность к аттестации и список событий ограничены по объёму,
  когорты считаются в SQL.

### Готовность к запуску
- Healthcheck для admin, client и pwa в `docker-compose.prod.yml`;
  необязательные настройки речи (Whisper, LLM) пробрасываются в воркер.
- Образ воркера без dev-зависимостей.
- CI: сборка всех Docker-образов без публикации, `npm audit` (пока не
  блокирует), Dependabot; тесты api-client в CI и `npm run verify`
  (`VERIFY_DOCKER=1` — образы и аудит локально).
- Порог покрытия для mobile-тестов; манифест приватности iOS.
- Админ платформы — только со вторым фактором: консоль `/platform` и доступ в
  любой клуб открываются сессии, вошедшей с кодом из письма и кодом из
  приложения-аутентификатора (`PLATFORM_ADMIN_MFA_REQUIRED`, в production по
  умолчанию включено). Подключение — `/platform/security`; неверные коды из
  приложения считаются в блокировку входа; сброс потерянного телефона —
  `deploy/README.md`.
- Удаление аккаунта — только с кодом из письма: приложение, экран согласия и
  веб-профиль запрашивают код на почту аккаунта (`POST /send-auth-code`) и
  удаляют через `POST /me/delete-account` с ним (`DELETE /me` убран). Код
  проверяется как при входе: неверный считается в блокировку входа.
- Content-Security-Policy на admin, app и pwa: скрипты только свои (в Next —
  по nonce на каждый запрос, поэтому все страницы рендерятся по запросу),
  сеть — только API, его сокет, хранилище, Sentry при DSN и Метрика при
  `YANDEX_METRIKA_ID`; встраивать сайты во фреймы нельзя. Иконки и пустое
  видео плеера Plyr — свои, без CDN. Подробности — `deploy/README.md`.
- Список участников постранично: `GET /workspaces/:id/members` принимает
  `curPage`/`perPage` (50 по умолчанию, не больше 200), поиск `q` (имя,
  e-mail, телефон, родитель), сегменты `access`, `sort` и `staffOnly`, отдаёт
  `total`/`curPage`/`perPage`; прогресс и отметки считаются только для
  страницы. В админке — «Показать ещё» и поиск на сервере; выбор тренеров
  грузит только персонал, запись на занятие — поиск по мере ввода.
- Уведомления в Telegram (необязательно, `TELEGRAM_BOT_TOKEN`,
  `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`): в настройках уведомлений
  приложения «Telegram → Подключить» открывает бота по одноразовой ссылке
  (`POST /me/telegram/link`, 15 минут), «Start» привязывает чат
  (`POST /telegram/webhook` с секретом), дальше копии уведомлений приходят в
  чат через очередь `telegram` с учётом выключенных клубов; `/stop`,
  «Отключить» или блокировка бота отвязывают. Chat id попадает в выгрузку
  данных и стирается при удалении аккаунта. Настройка — `deploy/README.md`.
- Сессия админки: refresh-токен — в HttpOnly-cookie `cs_refresh` на домене API
  (только для запросов с `X-Token-Transport: cookie` с адреса админки), access —
  только в памяти вкладки; обновление токена сериализовано между вкладками.
  Мобильное приложение, PWA и сайт — как раньше, токены в теле ответа. После
  деплоя админам нужно один раз войти заново.
